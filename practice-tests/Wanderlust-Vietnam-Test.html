Wanderlust Vietnam

App Development Test

Duration120 minutes
Total100 marks
DeliverableOne iOS app
FrameworkSwiftUI

Create an iPhone app for exploring destinations in Vietnam. Implement the screens and behaviours specified below. Match the provided visual references as closely as possible while keeping the app usable on a standard portrait iPhone.

Instructions

  1. Create a new Xcode iOS project named Wanderlust Vietnam.
  2. Use SwiftUI for all five screens. The visual references show the required light appearance.
  3. Load the destinations from the bundled JSON file. Do not hard-code the four records into the views.
  4. Organise the project into Model, ViewModel, and View groups. Use a SwiftUI observation approach so changes appear immediately.
  5. Use SwiftData for saved destinations and AppStorage for the appearance setting.
  6. Ensure the app launches, all navigation works, and user choices persist after relaunch.

Provided resources

Import the supplied destination photos, app icon image, Sacramento font, and destinations.json into the project. Create the named colours specified below.

Screen requirements

TASK 01 Welcome 12 marks

This is the first screen shown when the app launches.

  • Place the supplied logo in a vertically centred column. Display it at approximately 200 × 200 pt with aspect-fit scaling.
  • Show Wanderlust Vietnam below the logo in a bold system font of approximately 40 pt, coloured BrandPrimary.
  • Display your name and student ID on separate centred lines in Sacramento, approximately 35 pt, coloured BrandSecondary.
  • Place a rounded BrandPrimary button labelled Explore Destination below the text. Tapping it opens the Destinations screen.
  • Tapping the logo animates one complete rotation. The logo tap must not open another screen.

TASK 02 Destinations 18 marks

Show the four destinations in the order supplied by the JSON file.

  • Use a navigation title reading Destinations and a vertically scrolling collection of rows.
  • Each row contains the destination's main image at approximately 80 × 80 pt with rounded corners, followed by the name in bold BrandPrimary text at approximately 24 pt and the headline in BrandSecondary text at approximately 16 pt.
  • Keep approximately 8 pt side inset and 6 pt vertical spacing around rows. Allow long headlines to wrap without clipping.
  • Tapping a row opens the corresponding Detail screen. A heart button in the toolbar opens Saved. A gear button opens Settings as a sheet.
  • If the JSON cannot be loaded, show an error message in place of the rows.

TASK 03 Destination detail 20 marks

The selected destination determines every image and text value on this screen.

  • Show an inline navigation bar with the selected destination name in the centre and a leading Destination back control. Include a trailing save button with an outline or filled heart.
  • At the top of the scrollable content, display the main image full width at approximately 400 pt high, aspect-fill and clipped.
  • Below it, show the destination name in a bold title font using BrandPrimary, followed by the province in a caption font using BrandSecondary.
  • Add a thin divider, the complete description with approximately 20 pt horizontal inset, and a horizontally scrolling gallery.
  • Show all three gallery images in JSON order. Each gallery image is approximately 120 × 120 pt with a 15 pt corner radius.
  • Tap the heart to save or unsave the destination. The icon changes immediately and stays correct when the screen is reopened.

TASK 04 Saved destinations 18 marks

This screen lists the destinations saved by the user.

  • Store saved destination IDs locally using SwiftData, with one saved record per destination ID.
  • Give the screen a navigation title of Saved. Display saved destinations with the same row style as the Destinations screen and preserve their JSON order.
  • When there are no saved items, show a centred heart symbol and the message No saved destinations.
  • Tapping a saved row opens its Detail screen. If the item is unsaved there, it disappears from Saved when the user returns.
  • Saved items must remain after the app is terminated and relaunched. Repeatedly saving one destination must not create duplicates.

TASK 05 Settings and appearance 12 marks

Present Settings as a modal sheet from the Destinations screen.

  • Use an inline navigation title Settings and a top-right Done button that dismisses the sheet.
  • Use a grouped Form with an Appearance section containing one native switch labelled Dark Mode.
  • Changing the switch immediately changes the app's colour scheme. All screens must remain readable in light and dark appearance.
  • Store the user's choice with AppStorage. Closing and relaunching the app must preserve the selected appearance.

Acceptance checks

  1. Launch the app. Tap the logo and verify the rotation. Tap Explore Destination and verify that exactly four destinations appear.
  2. Open Hoi An Ancient Town. Verify the main image, Quang Nam, the complete description, and three gallery images.
  3. Save Hoi An and return to the list. Open Saved and confirm that Hoi An appears. Open it, unsave it, and confirm that the empty state appears.
  4. Save two destinations, terminate the app, and relaunch. Confirm both remain saved.
  5. Open Settings, enable Dark Mode, close the sheet, visit all screens, and relaunch. Confirm the appearance is still dark.

Submission

Submit the complete Xcode project. The project must include all resources required to build and run the app. Verify the final project on an iPhone simulator before submission.
