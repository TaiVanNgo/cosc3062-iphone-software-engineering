Campus Compass

App Development Test

Duration120 minutes
Total100 marks
DeliverableOne iOS app
FrameworksSwiftUI · MapKit · SwiftData

Build an iPhone app that helps students discover useful campus places and record the places they have visited. Implement the five screens and interactions below. Match the visual references in portrait orientation.

Instructions

  1. Create a new Xcode iOS app project named Campus Compass.
  2. Build all five screens with SwiftUI. Use navigation and sheets as specified.
  3. Read the four places from the supplied spots.json. Do not enter their content directly in the views.
  4. Organise the code into Model, ViewModel, and View groups. Use an observation approach for changing UI state.
  5. Use SwiftData to store visited place IDs and AppStorage to store the appearance preference.
  6. The finished app must build and run on an iPhone simulator.

Provided data

The JSON file contains four places. Each object has an ID, name, category, building, summary, description, opening hours, SF Symbol name, latitude, and longitude.

Order: Learning Commons, Makerspace, Garden Courtyard, Campus Café.

Use the SF Symbols named in the JSON. The preview glyphs represent the symbols; the final app should use native SF Symbols.

Screen requirements

TASK 01Welcome 10 marks

Show this screen when the app starts.

  • Centre a large circular compass mark, approximately 170 × 170 pt. Construct it from SwiftUI shapes and an arrow or suitable SF Symbol. Use Primary and Secondary.
  • Place the title Campus Compass underneath in bold system text at approximately 38 pt, followed by the subtitle Find your next place in Secondary at approximately 18 pt.
  • Show your name and student ID on separate, centred lines near the main button.
  • A rounded Primary button labelled Explore Campus opens the Places screen. Back navigation returns to Welcome.

TASK 02Places 20 marks

Display the four JSON places in file order.

  • Use a large navigation title Places. Put a map button and a gear button at the right of the navigation bar.
  • At the top of the content, display “X of 4 visited” and a thin progress bar showing the visited fraction. Animate changes to the progress bar.
  • Add an All / Visited segmented control. All shows every place; Visited shows only places with a SwiftData visit record. When none are visited, display a centred No places visited yet message.
  • Each row contains a 60 pt circular category icon with the correct category colour, the name in bold, building underneath, and category in Secondary. Show a small checkmark at the right when visited.
  • Tap a row to open its Detail screen. The map button opens Map; the gear opens Settings as a sheet.

TASK 03Place detail 22 marks

All displayed content must correspond to the selected JSON place.

  • Show an inline navigation bar with a Back control and the place name. The content below it scrolls vertically.
  • Create a rounded hero panel, approximately 220 pt high, using the category colour. Centre a large SF Symbol and the uppercase category name in this panel.
  • Below the panel, show the place name in bold Primary text at approximately 30 pt, then the building in Secondary. Show the summary as a separate paragraph.
  • Show an Opening hours information card and the full description. Use about 18 pt horizontal content padding.
  • At the bottom, use a full-width button labelled Mark as Visited or Remove Visit, depending on current state. Saving or removing a visit updates the list and map immediately and persists after relaunch.

TASK 04Campus map 20 marks

Use MapKit and the coordinates supplied in the JSON file.

  • Show an inline navigation title Map and a Back control. Centre the initial map region so all four places are visible.
  • Place one marker for each spot at its latitude and longitude. Use the category colour and SF Symbol for each marker. A visited marker should display a visible checkmark or another clear visited indicator.
  • When a marker is tapped, show a compact bottom card with the place icon, name, building, and a chevron or View Details control.
  • Tapping the bottom card opens the selected place's Detail screen. Returning to Map keeps the selected marker and reflects any visit change.
  • The map must support normal panning and zooming. It must not require the user's current location.

TASK 05Settings 10 marks

Present Settings as a modal sheet from the Places screen.

  • Use an inline navigation title Settings and a top-right Done button that dismisses the sheet.
  • Use a grouped Form with one Appearance section containing a native switch labelled Dark Mode.
  • Switching appearance changes every screen immediately and keeps text, markers, buttons, and cards readable. Persist the setting with AppStorage.
  • The setting must remain after the app is closed and reopened.

Acceptance checks

  1. Launch the app and open Places. Confirm all four names, buildings, categories, and icons match the JSON order.
  2. Open Learning Commons, mark it visited, return to Places, and confirm the count becomes 1 of 4 visited and the progress bar advances.
  3. Select the Visited segment. Confirm only Learning Commons appears. Remove its visit and confirm the empty state appears.
  4. Open Map. Confirm four markers appear. Select Campus Café, open its detail from the bottom card, and mark it visited. Return to Map and confirm its marker indicates visited status.
  5. Terminate and relaunch the app. Confirm the visit is retained. Turn Dark Mode on, relaunch again, and confirm the appearance remains dark.

Submission

Submit the complete Xcode project, including spots.json and all required asset colour definitions. Verify the final project on an iPhone simulator before submission.
